Build a localization-ready marketing website for a fictional boutique dairy supplier called "Meadow & Churn" (or suggest a better name). The site must support instant switching between English and Urdu (or English and French — your choice) with no page reload, using a JSON-based translation system. Use Tailwind CSS for all styling. Use plain HTML/CSS/JS with vanilla JS for the language switch — simpler to demo than a framework.

Build this in the following order, and pause after each task so I can review before you continue:

Task 1 — Project scaffold
Set up a basic project structure: index.html, /css (Tailwind config/output), /js, /locales (en.json, ur.json or fr.json). Include Tailwind via CDN or build step (your choice, but document which). Confirm the scaffold runs before continuing.

Task 2 — Page structure & content (English only first)
Build these sections with real (not placeholder) copy for a boutique dairy supplier: Header/Nav, Hero, About/Our Story, Products (milk, cheese, yogurt, ghee — at least 4-6 product cards with name, description, price), Sourcing/Farm practices section, Testimonials, Contact/Order form, Footer. Use semantic HTML and Tailwind utility classes only — no custom CSS unless unavoidable.

Task 3 — Translation system
Every visible string must be wrapped in an element with a data-i18n="key" attribute. Build en.json and ur.json (or fr.json) with matching keys for every string on the page. Write a small JS module that: loads the JSON files, replaces text content based on the current language, and updates dir="rtl" on <html> automatically if the language is Urdu/Arabic (skip this if using French).

Task 4 — Language switcher UI
Add a language toggle in the header (flag icons, dropdown, or buttons for "EN" / "UR"). Clicking it should swap all text instantly with no reload, and remember the user's choice using localStorage so it persists on refresh.

Task 5 — Responsive & polish pass
Make sure the site works cleanly on mobile, tablet, and desktop. Use Tailwind's responsive prefixes (sm:, md:, lg:). Add hover states, transitions, and consistent spacing/typography.

Task 6 — Edge case testing
Test and fix: missing translation keys (should fall back to English, not show blank/undefined), very long product names/descriptions in one language breaking layout, switching language mid-scroll, rapid repeated clicking of the toggle, and page behavior with JavaScript slow to load. List each issue found and how you fixed it as you go — I'll use this list directly in my documentation.

Task 7 — Write README.md
Generate a complete README.md file in the repo root covering: (1) project overview and purpose, (2) tech stack and why each tool was chosen, (3) how the translation system works technically (file structure, data-i18n attributes, fallback logic), (4) how to add a third language step-by-step, (5) the edge cases tested from Task 6 and how each was fixed, (6) known limitations, (7) what you'd improve with more time. Write it in clear, professional language suitable for a hiring manager to read with no other context.
